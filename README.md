# CRM для автосервиса

CRM для автомастерской на **Ruby on Rails 8.1** и **PostgreSQL 17**, запускается в контейнерах (Docker или Podman).

Проект вырос из переноса [ChurchCRM](https://github.com/ChurchCRM/CRM) на Rails.

## Возможности

- **Заказ-наряды**: приём автомобиля с пробегом и жалобой клиента, мастер, срок готовности, статусы «Принят → В работе → Ждёт запчасти → Готов → Выдан», отмена с возвратом запчастей на склад, печатная форма с подписями
- **Работы и запчасти в заказе**: из справочника (цена подставляется с учётом сложности, например «Внедорожник») или произвольные с сохранением в справочник, несколько исполнителей на одну работу с долями участия, товар клиента без списания со склада, отдельные скидки на работы и запчасти и скидка в рублях
- **Печатные формы**: заказ-наряд, акт приёма автомобиля (топливо, повреждения, комплектность), акт выполненных работ, счёт на оплату с банковскими реквизитами и суммой прописью
- **Календарь на месяц** и **доска нарядов** с перетаскиванием карточек между статусами
- **Оплаты**: наличные, карта, безнал, частичная оплата, остаток к оплате
- **Клиенты**: частные лица и компании с ИНН, поиск по фамилии, телефону, госномеру или VIN, фиксированная или накопительная скидка по ступеням, рекламные источники
- **Автомобили**: марка, модель, год, VIN, госномер, пробег (обновляется из заказ-нарядов), история обслуживания
- **Запись на приём**: календарь на день по постам, запись кликом по свободному слоту, проверка занятости поста и мастера, статусы «Записан → Подтвердил → Приехал / Не приехал», из записи одной кнопкой создаётся заказ-наряд
- **Заявки**: воронка обращений (новая → в работе → записан → пришёл / отказ с причиной), автопривязка к клиенту по телефону, создание клиента и запись из заявки, конверсия по источникам
- **Сметы**: наряд в статусе «Смета» без движения склада, печать предварительной сметы, после согласования — в работу со списанием запчастей
- **Напоминания о ТО**: интервалы по времени и пробегу у работ, автоматически при выдаче наряда, оценка пробега по истории визитов, список «Кому позвонить» с записью, отметкой звонка и отсрочкой
- **Задачи** сотрудникам с привязкой к клиенту, машине, наряду или заявке
- **Справочник работ** с кодами, нормо-часами и ценами
- **Склад**: наценка по диапазонам закупочной цены, категории, отчёт «Требуется заказать» с созданием прихода, запрет минусовых остатков, поставщики и приходные накладные со средней себестоимостью, списания и инвентаризация, журнал движения по каждой позиции, ячейки хранения, OEM-номера и аналоги, автоматическое списание в заказ-нарядах
- **Продажа запчастей** с прилавка, без заказ-наряда
- **Финансы**: кассы и счета с остатками, единый журнал денег (оплаты, продажи, зарплата попадают туда сами), расходы и доходы по статьям, переводы между кассами, оплаты и долги поставщикам
- **Зарплата**: оклад, процент от выполненных работ и процент от заказов приёмщика, премии и штрафы, выплаты из кассы
- **Отчёты**: поступления и расходы, средний чек, работы по видам и исполнителям, наценка на запчасти, рекламные источники, стоимость склада; любой список и отчёт выгружается в Excel (CSV)
- **Импорт и экспорт**: загрузка клиентов с автомобилями, запчастей с остатками, работ и поставщиков из CSV или Excel по шаблону, с автоматическим сопоставлением колонок, предпросмотром, выбором «пропустить или обновить дубли» и файлом ошибок; перенос истории из S+ (splus.ru) по трём отчётам с сохранением номеров нарядов; выгрузка всей базы одним ZIP-архивом
- **Персональные данные (152-ФЗ)**: отдельное согласие на обработку ПДн и согласие на рекламу с печатной формой и историей, обезличивание клиента и автоматическое по сроку хранения, журнал действий (входы, просмотры, выгрузки), двухфакторный вход, автоматический выход, публичная политика обработки ПДн, шифрованные резервные копии
- **Настройки сервиса** в программе: реквизиты для документов, банк, условия в заказ-наряде, уровни сложности, ступени скидок, наценки, категории
- **Главная**: машины в работе по статусам, готовые к выдаче, просроченные, выручка, заканчивающиеся запчасти
- **Сотрудники и пользователи** с правами: клиенты и автомобили, заказ-наряды, справочники и склад, приём оплат, финансы и зарплата, отчёты, удаление
- Интерфейс на русском и английском, тёмная тема по настройке системы

## Настройка

| Переменная | Назначение | По умолчанию |
|------------|------------|--------------|
| `SHOP_NAME` | Название сервиса в печатной форме | WrenchCRM |
| `SHOP_DETAILS` | Адрес и телефон в печатной форме | — |
| `CURRENCY_UNIT` | Знак валюты | ₽ |
| `TIME_ZONE` | Часовой пояс | Europe/Moscow |
| `WORKDAY_START`, `WORKDAY_END` | Часы работы в календаре записи | 9, 20 |
| `SEED_DEMO` | `1` — загрузить демо-данные в продакшне | — |

## Установка

Нужен Docker (на Windows и macOS — Docker Desktop) или Podman.

1. Скачайте архив последней версии со страницы [Releases](https://github.com/SitHond/WrenchCrm/releases): `.zip` для Windows, `.tar.gz` для Linux и macOS.
2. Распакуйте и запустите `install.ps1` (Windows) или `install.sh` (Linux, macOS).
3. Откройте http://localhost:3000.

Скрипт спросит данные администратора, сгенерирует пароли и запустит программу из готового образа `ghcr.io/sithond/wrenchcrm`. Обновление, резервное копирование и доступ по сети описаны в [deploy/README.md](deploy/README.md).

## Сборка из исходников

```bash
cp .env.example .env          # задайте пароли и SECRET_KEY_BASE (openssl rand -hex 64)
docker compose up -d --build  # или: podman compose up -d --build
```

При каждом старте контейнер применяет миграции и создаёт администратора, если его ещё нет.

## Разработка

```bash
docker compose -f compose.dev.yaml up --build
```

Код монтируется в контейнер, изменения подхватываются без пересборки. Загружаются демо-данные, вход `admin@example.com` / `changeme123`.

```bash
docker compose -f compose.dev.yaml exec web bin/rails test
docker compose -f compose.dev.yaml exec web bin/rails console
```

Без контейнера понадобятся Ruby 3.4 и PostgreSQL. Подключение задаётся переменными `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD` (по умолчанию `localhost:5432`, `wrench_crm`/`wrench_crm`).

## Выпуск версии

Тесты запускаются в GitHub Actions на каждый push в `main`. Чтобы выпустить версию, поставьте тег:

```bash
git tag v1.2.0
git push origin v1.2.0
```

Workflow [release.yml](.github/workflows/release.yml) прогонит тесты, соберёт образ для amd64 и arm64, опубликует его в `ghcr.io/sithond/wrenchcrm` с тегами `1.2.0`, `1.2` и `latest` и создаст релиз с архивами установки и списком изменений. Тег с дефисом (`v1.3.0-beta.1`) публикуется как предварительный релиз и не меняет `latest`.
