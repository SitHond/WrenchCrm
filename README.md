# CRM для автосервиса

CRM для автомастерской на **Ruby on Rails 8.1** и **PostgreSQL 17**, запускается в контейнерах (Docker или Podman).

Проект вырос из переноса [ChurchCRM](https://github.com/ChurchCRM/CRM) на Rails.

## Возможности

- **Заказ-наряды**: приём автомобиля с пробегом и жалобой клиента, мастер, срок готовности, статусы «Принят → В работе → Ждёт запчасти → Готов → Выдан», отмена с возвратом запчастей на склад, печатная форма с подписями
- **Работы и запчасти в заказе**: из справочника (название и цена подставляются) или произвольные, скидка клиента подставляется автоматически
- **Оплаты**: наличные, карта, безнал, частичная оплата, остаток к оплате
- **Клиенты**: частные лица и компании с ИНН, поиск по фамилии, телефону, госномеру или VIN
- **Автомобили**: марка, модель, год, VIN, госномер, пробег (обновляется из заказ-нарядов), история обслуживания
- **Запись на приём**: календарь на день по постам, запись кликом по свободному слоту, проверка занятости поста и мастера, статусы «Записан → Подтвердил → Приехал / Не приехал», из записи одной кнопкой создаётся заказ-наряд
- **Справочник работ** с кодами, нормо-часами и ценами
- **Склад запчастей**: остатки, приход, автоматическое списание в заказ-нарядах, минимальный остаток
- **Главная**: машины в работе по статусам, готовые к выдаче, просроченные, выручка, заканчивающиеся запчасти
- **Сотрудники и пользователи** с правами: клиенты и автомобили, заказ-наряды, справочники и склад, приём оплат, удаление
- Интерфейс на русском и английском, тёмная тема по настройке системы

## Настройка

| Переменная | Назначение | По умолчанию |
|------------|------------|--------------|
| `SHOP_NAME` | Название сервиса в печатной форме | WrenchCRM |
| `SHOP_DETAILS` | Адрес и телефон в печатной форме | — |
| `CURRENCY_UNIT` | Знак валюты | ₽ |
| `TIME_ZONE` | Часовой пояс | Europe/Moscow |
| `WORKDAY_START`, `WORKDAY_END` | Часы работы в календаре записи | 9, 20 |
| `SEED_DEMO` | `1` — загрузить демо-данные в продакшне | — |

## Установка

Нужен Docker (на Windows и macOS — Docker Desktop) или Podman.

1. Скачайте архив последней версии со страницы [Releases](https://github.com/SitHond/WrenchCrm/releases): `.zip` для Windows, `.tar.gz` для Linux и macOS.
2. Распакуйте и запустите `install.ps1` (Windows) или `install.sh` (Linux, macOS).
3. Откройте http://localhost:3000.

Скрипт спросит данные администратора, сгенерирует пароли и запустит программу из готового образа `ghcr.io/sithond/wrenchcrm`. Обновление, резервное копирование и доступ по сети описаны в [deploy/README.md](deploy/README.md).

## Сборка из исходников

```bash
cp .env.example .env          # задайте пароли и SECRET_KEY_BASE (openssl rand -hex 64)
docker compose up -d --build  # или: podman compose up -d --build
```

При каждом старте контейнер применяет миграции и создаёт администратора, если его ещё нет.

## Разработка

```bash
docker compose -f compose.dev.yaml up --build
```

Код монтируется в контейнер, изменения подхватываются без пересборки. Загружаются демо-данные, вход `admin@example.com` / `changeme123`.

```bash
docker compose -f compose.dev.yaml exec web bin/rails test
docker compose -f compose.dev.yaml exec web bin/rails console
```

Без контейнера понадобятся Ruby 3.4 и PostgreSQL. Подключение задаётся переменными `DB_HOST`, `DB_PORT`, `DB_USER`, `DB_PASSWORD` (по умолчанию `localhost:5432`, `wrench_crm`/`wrench_crm`).

## Выпуск версии

Тесты запускаются в GitHub Actions на каждый push в `main`. Чтобы выпустить версию, поставьте тег:

```bash
git tag v1.2.0
git push origin v1.2.0
```

Workflow [release.yml](.github/workflows/release.yml) прогонит тесты, соберёт образ для amd64 и arm64, опубликует его в `ghcr.io/sithond/wrenchcrm` с тегами `1.2.0`, `1.2` и `latest` и создаст релиз с архивами установки и списком изменений. Тег с дефисом (`v1.3.0-beta.1`) публикуется как предварительный релиз и не меняет `latest`.
